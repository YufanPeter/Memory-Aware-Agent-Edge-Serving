## P4

(naive) = ours' first TRIM runs, before the shrink-fast fix: there the compaction request waited in the gate queue like any other, and its own slot could be given up while it waited. The fixed rows (post hoc) dispatch a request that only shrinks its own resident slot at once. Agents = time-mean agents in flight (max = the manager's peak count). Give-ups = give-up events (one per task and idle period, so a drop then an erase is one), with the victims by action off/drop/erase summed from the per-task manager counters (tasks.jsonl); – = no manager in the run. Recompute = re-prefilled tokens per task from the traces, without the compaction pairs; trim-lost = tokens removed or re-prefilled at a compaction (module docstring). Prefill tok/task = every prompt token the server computed. Restore-bound viol. = restores whose image exceeded the gate's reservation (the image is dropped and re-prefilled instead).
